# Seatshare · 通勤座位信息共享 H5（验证版）

单线路验证用原型：乘客自发共享"我将在哪站下车"，让站着的人提前知道哪节车厢即将有空位。**纯前端、无后端、无登录、数据存本机浏览器。**

## 怎么运行

方式一（最快）：直接双击 `index.html` 用浏览器打开。

方式二（发给别人测试）：

```bash
cd Seatshare
python3 -m http.server 8080
# 手机和电脑连同一 WiFi，手机访问 http://<电脑IP>:8080
```

正式分享时，把这三个文件（`index.html` `style.css` `app.js`）扔到任意静态托管即可（Vercel / Netlify / 腾讯云 COS 静态网站 / GitHub Pages）。

## 功能

| 页面 | 说明 |
|---|---|
| 找空座 | 选线路/方向/所在站，显示前方 6 站内将空出的座位（车厢号 + 下车站 + 倒计时） |
| 我要下车 | 选车厢 + 当前站 + 下车站，10 秒发布；可随时撤销 |
| 数据 | 累计发布 / 查询 / 坐上了 / 命中率 / 供给覆盖率 |

内置机制：
- 信息有效期：预计到站后 **2 分钟**自动失效
- 列车过站校验：车已开过你所在的站，信息不再展示
- 举报：**3 次**自动隐藏
- 匿名：只展示车厢号和下车站，无任何身份信息

## 演示数据

首次打开预置了 5 条「9 号线」示例（卡片上标"演示数据"），默认站在九亭。**正式验证前删掉**：`app.js` 里搜索 `seed()`，把 `load()` 中的调用注释掉即可。

## 怎么判断验证成不成立

跑两周，只看数据页两个数：

1. **命中率 ≥ 30%**：查过信息的人里，有多少真坐上了。低于 30% 说明信息没用。
2. **供给覆盖率**：一节车厢 40 座中已知去向的比例。一趟车 40 座只有不到 2 人发布（<5%），说明没人愿意发，产品不成立。

另外手动观察一项（产品算不出来）：在车上数一节车厢，看有多少坐着的人愿意掏出手机发一条。这是真实的上传率。

## 接后端的位置

都在 `app.js`，替换三处即可：

- `seed()` / `load()` / `save()` → 换成 HTTP 请求 + 服务端存储
- `visiblePosts(now)` → `GET /posts?line=&dir=&station=`
- 发布按钮里的 `db.posts.push(p)` → `POST /posts`

注意：真实部署需要处理信息时效（服务端按 `arriveAt` 过期清理）、防刷（同一设备限频）、以及隐私（绝不收集身份与精确行程关联）。

## 已知限制

- 站间时间按固定 2 分钟估算，未考虑停站差异与列车实际位置（真实版应接入官方列车位置数据）
- 车厢号依赖用户查看车门上方编号，实际填写率可能很低——这是本次验证要回答的核心问题之一
- 车厢内手机信号差，会影响发布与查询体验，无法在前端解决
